# 迭代 8：导入保真与展示一致性

日期：2026-09-23。范围仍是保存后的非流式 Eino 结果查看；不增加实时、执行、发布或部署。
这轮直接修复整体复查中确认的技术问题，没有停留在建议，也没有增加一级界面或说明面板。

## 已修复

| 问题 | 处理 | 验收边界 |
| --- | --- | --- |
| Go 的大整数在浏览器解析后静默变值 | 解析前检查数字 token；对象入口拒绝非安全整数 | 原值不改写，不转字符串，不接受已变值结果 |
| 极深 metadata 触发调用栈异常 | 迭代式、有限深度/大小/值数预检；统一入口拒绝 | 8,000 层输入产生结构化错误，保留旧结果和选择 |
| Run Record 的 getter 会被执行、稀疏数组被接纳 | 按属性描述符检查普通 JSON 数据 | getter 调用为零；隐藏字段、稀疏数组、循环明确拒绝 |
| 同一事件有 error 和 Tool 返回时，工作台隐藏独立返回 | 路径与嵌入共用错误项识别；轨迹按真实来源值决定展示 | 错误与业务原文分别保留，即使工具 JSON 与错误对象同文 |
| 最终结果漏读正文截断 metadata | 根、步骤和局部调用共用 capture 状态规则 | 同一来源、同一状态；无关或无法定位的诊断不猜归属 |

复查时还修复了工具参数/返回 JSON 文本的二次解析：无法精确保留数值时，保持它作为
原始字符串，而不是先把其中的数字舍入后展示。格式化未应用草稿也使用同一解析边界。
来源跳转检查草稿是否等于已接受记录时，同样不会用有损解析抹掉用户未应用的文本。
拒绝导入时直接显示简短原因和“当前结果已保留”，不再要求先打开校验详情才能知道
数值、深度或容量问题；详细诊断仍保留在原入口，没有增加常驻说明文案。

## 有意采用的策略

- 数字类型：接受 JavaScript 安全整数范围和普通有限小数。文本导入额外比较十进制有效值，
  允许 `1.2300e2` 等等价拼法，拒绝有效位丢失、溢出和非零数下溢。未引入任意精度数值类型。
- 数字形态的字符串是正常业务数据，不扫描其内容后拒绝整份记录，也不改变其类型。
- 对象 API 只能检查调用时已有的值，不能恢复调用方更早的解析损失。
- 输入安全边界为最大深度 128、1,000,000 个值、64 MiB；安全预检至多返回 20 条诊断。
  文件在读取前检查字节数；粘贴文本与对象也各有独立检查。共享引用按实际 JSON 展开计入预算，
  不能通过反复引用一个对象绕过容量限制。既有 10,000 条证据样例及其规范投影仍可打开。
- Recorder 的无索引诊断只有相对正文路径，不能用它猜测是哪条信封被截断；已确认归属
  来自该信封的 capture metadata，或内部解释 API 的精确索引诊断。未扩展公共协议字段。

## 新增真实记录与测试

新增 [数值边界记录](../fixtures/input-boundaries/README.md)，独立于原有 28 份业务矩阵：

- `graph-safe-integers.json`：真实 Graph Invoke，根/节点输入输出保留安全整数边界及
  64 位极值的字符串。前端必须正常打开、复制和查看原始来源。
- `graph-unsafe-integers.json`：同样是真实运行，Go 精确保留 int64/uint64 极值；
  前端必须明确拒绝，不能把它们展示成舍入值。拒绝是正确验收结果，不代表 Go 执行失败。

Go 测试按原始 token 检查，不经过 float64，以免测试自身掩盖舍入。生产 Go、原协议与
旧 28 份样例未修改。深度、错误与 Tool 共存、截断组合等变体属于前端合成测试，单独标注。

新增单元入口 `json-input-boundary`、`record-input`；新增浏览器入口 `input-boundaries`、
`reading-consistency`。验证文件/粘贴/对象导入、正文与来源、复制和离线原始字节导出、
拒绝后的状态/草稿保留，以及同源正文在路径、轨迹、嵌入和离线中的一致性。

## 验收

最终固定构建的三浏览器全套 **513 / 513 通过**，Chromium、Firefox、WebKit 各 171 项；
4 个并行 worker，耗时 198.9 秒，无跳过、无失败、无重试转绿。
机器记录见 [最终浏览器报告](../.artifacts/iteration-8/browser-final.json)。

已通过语法检查、17 个 JS 单元入口、类型检查、站点/离线构建；新增 10 项 Chromium
定向检查全部通过。真实 Go 数值测试通过 `-race -count=1`。没有重新运行全部 Go 测试，
不把上轮结果计作本轮新验证。

人工打开最终构建，导入超出安全整数范围的真实 Go 记录，确认页面直接提示
“整数超出精确范围；当前结果已保留。”，原来的最终回答、输入和耗时仍可查看。
9 个包入口的 ESM/CJS 构建均可加载，导出名称一致。

首轮定向测试发现并修正了测试本身的三个问题：复制按钮选择器过期、测试变量与 DOM
命名属性冲突，以及把内部索引字段放进不支持它的 Run Record 诊断中。没有为使测试通过
而放宽协议；最终测试使用合法记录，并单独验证内部 API 的索引诊断。

首次完整回归为 511 / 513：Firefox 压力用例超时，WebKit 在测试期间重新构建导致
资源 404。Firefox 单独复跑通过；随后冻结构建、使用 4 个 worker 重跑全部 513 项，
得到以上最终结果。没有增加超时、删除检查或开启失败重试。

## 保留边界

- 原有四项矩阵限制不变：两份旧 Graph 没有 I/O 正文、一份超限省略、一份并发 Agent
  身份未确认。仍然不虚构缺失结果或调用关系。
- 字节、深度、数值限制是明确的兼容收紧；以前会静默变值或可能失控的输入现在会被拒绝。
  大整数的无损交互展示仍未实现，不将本轮描述为已支持任意精度数字。
- 普通跨 realm 对象可通过嵌入式防御复制；直接 Graph 投影仍受兼容依赖已有校验限制，
  未修改上游来扩大这项能力。
- `eino-workflow-dag` 工作区仍干净，停留在已发布版本对应的 `286f3d7`。

下一轮候选仍是多步骤 Graph 循环与 Workflow 并行汇聚的真实业务链路验收。
本轮不以修复保真问题为由扩大到新 Agent 语义或监控平台。
