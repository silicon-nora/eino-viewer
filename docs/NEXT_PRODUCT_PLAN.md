# 下一阶段：首次接入与陌生记录阅读

日期：2026-09-24。状态：本期工程工作已完成；见[本期验收记录](./FIRST_USE_ACCEPTANCE.md)。
以下保留开工前方案及基线，历史 597 次不代表本轮执行数。人类阅读速度与陌生用户效果仍待验证。

## 1. 决策与目标

下一步不增加一级功能，也不继续以测试数量衡量进度。把已有能力变成更容易接入、读懂、核对的产品：

> 第一次接触项目的人，能选对查看入口；打开一份不熟悉的已完成记录后，能准确说明结果、实际路径和证据边界。

保留“专业阅读工作台”的浅色、蓝色、结果优先、路径为主区方向。Agent、Graph、Workflow 保留各自的阅读语义，工作台、完整嵌入和离线版使用一致的核心阅读规则。

本期按三轮推进：**接入与阅读基线 → 修复已证实的主要障碍 → 复验并收口**。没有证据的体验猜测不直接变成开发任务。

## 3. 第一轮：接入路线与阅读基线

### 3.1 先验证并修复导入启动耦合

先在浏览器模拟示例文件 404、无效 JSON 和持续等待，确认其对打开文件、粘贴、拖放的影响，再实施最小隔离：核心查看能力就绪后即可导入，示例资源的状态只影响示例选择。可按需加载示例，但不新增示例 URL 参数，不改变选择具体示例才替换记录的规则。

验收：示例缺失、损坏或等待时仍能打开合法自带记录；示例错误在就近位置反馈，不误报核心渲染器不可用；迟到的示例响应不替换用户已打开的记录。核心脚本真正失败时仍显示真实不可用状态，不假装可操作。保留一条 P1 故障隔离回归，复用现有导入保真断言，不铺开新的组合矩阵。

### 3.2 修正文档接入路线

实施时同步整理中英文 README 与 Go 接入文档的交叉入口：

- 只想查看 JSON：先指向工作台或已有离线版。
- 在自己的应用里嵌入完整结果阅读：推荐已有 `createEinoRunViewer`。
- 只需要底层画布、自行组织详情：保留 `createEinoViewer`，明确这是低层入口。
- 已有 Eino 程序需要生成记录：指向现有 Recorder 的非流式完成记录流程，不引入新的采集方式。

纠正范围联动、绘图阈值及检索字段描述。中英文仍有“摘要检索”说法，实际步骤索引是可见名称、身份、状态等结构字段，不包含正文摘要；以当前实现和既有检索契约为准，不为迎合旧文档扩展全文搜索。现有文档中已经正确的精度、安全、缺失和结束边界继续保留；不把正文改写成一份新 API 手册。

验收：中英文给出相同推荐；在依赖已经准备好的本地环境中，按文档完成一次 JSON 查看和一次完整组件嵌入；展示结果、路径、步骤详情并验证更新/销毁。不得借此发布包、修改上游或增加公共 API。

### 3.3 用六项任务建立阅读基线

先从已有记录取样，不新增 Recorder 场景，不重写 fixtures。任务只告诉读者要回答什么，不提示按钮位置或答案。

| 任务 | 现有代表记录 | 必须回答的事实 |
| --- | --- | --- |
| 识别整次结果 | `eino-agent-recorder-trip-planner-completed-v1` | 最终建议是什么、执行状态是什么、耗时来自哪里 |
| 查明失败 | `workflow-parallel-join-failed` | 哪一路失败、该步输入与原始错误、汇聚是否实际执行；不能把未执行解释成成功 |
| 区分根与子调用 | `agent-deep-nested-failure-recovered` | 根结果、中层处理和叶层失败分别是什么；能返回父级及全部步骤 |
| 读懂重复访问 | `graph-multistep-loop-failed` | 哪一次访问失败、前次成功结果是什么；不能混成一个节点结果 |
| 理解证据不足 | `graph-io-oversized`，辅以 `graph-io-redacted` 和 `workflow-definition-only` | 区分源正文省略、脱敏、未执行与界面折叠；不能将“未看到”解释为“没有发生” |
| 核对完整原文 | `graph-io-long` | 从结果找到来源并复制完整正文；界面预览不改变原值 |

记录文件均位于 `fixtures/`：带 `eino-` 前缀者在根目录，其余在 `recorder-matrix/`，文件后缀为 `.json`。十秒成功任务固定使用 `eino-agent-recorder-trip-planner-completed-v1`，十秒失败任务固定使用 `eino-agent-recorder-trip-planner-failure-completed-v1`，分别属于前两类任务的子任务；表中 Workflow 失败属于复杂任务，两者不混用时限。交付逐项列出这些子任务的结果，不允许临时更换更容易的记录。

工作台承担六项主要走查；嵌入与离线版各复核失败、层级、原文三条核心路径，不让同一读者反复完成所有入口组合。其余跨入口/浏览器组合继续由既有自动回归保护。

主要阅读环境为 1280×720；390×844 检查顺序和定位，1000px 宽嵌入容器检查宿主适配。只有修改了响应式规则时，再对四种既有验收尺寸（1440×900、1280×720、768×1024、390×844）完整复核。中英保持同一事实与任务定义。

记录：答案是否正确、是否需要提示、首次正确答案用时、误入/返回次数、卡住的具体位置。评分答案预先从原始记录和已有独立断言核对，不从当前 UI 反推；答案不提前提供给读者。

任务目标（非已有成绩，也不是性能 SLA）：

- 简短天气记录沿用[既有“十秒理解”目标](./EINO_RUN_VIEWING_PRODUCT.md#ten-second-comprehension)：通过首屏和一次节点选择，10 秒内识别问题、实际路径、天气结果与最终回答，同时辨认运行状态。这是待实测目标，不用更宽松的计时替代。
- 简短失败记录同样以 10 秒理解失败步骤、观察到的输入和原始错误为目标。复杂失败任务另设 90 秒核对目标，摘要到明确失败步骤仍须一次动作；不能用复杂任务时限降低简单记录要求。
- 三层调用：120 秒内分清根与叶的结果并返回上级。
- 所有任务的事实回答正确；任何将缺失当成功、子结果当根结果、重复访问混为一次的误判都必须记录，不能被平均完成率抵消。

人工计时从记录成功显示到首次正确回答，包含读者的浏览时间；不包含准备环境与传文件。开发者已知答案的计时只作内部对照，代理执行和工具等待的耗时不作为人类阅读数据。没有陌生读者时，上述阅读速度目标记为待验证，不以自测替代。超时表示阅读效率未达标，不等于事实错误；未达标项必须给出原因与处理决定，不能事后放宽目标后宣称通过。

产出：一份接入验证记录和一张阅读障碍清单。清单区分“确认缺陷”“可复现阅读障碍”“待验证偏好”，每项包含场景、复现步骤、影响、证据和最小修复范围。

### 3.4 独立工程约束 M1：避免验证任务互相干扰

依据[上轮故障记录](../tests/PRIORITIES.md#本轮验收结果)，并发浏览器任务曾因共用服务和产物导致中断。这不是待发现的 UI 问题，也不占三个体验优化名额。

在下一次完整回归前，为项目约定的 `npm run test:browser` 入口补轻量防重入检查，保护其构建到报告写入的完整过程。验收：第二次启动在构建前明确退出；首个任务正常结束、失败和收到中断信号后均可再次运行；强制结束后的残留占用须先核验原任务已退出才能恢复，不能停止无关服务或清除其他任务的报告。只保护约定入口，不承诺拦截绕过入口的手动命令，不引入新的调度系统。

## 4. 第二轮：只解决最重要的阅读障碍

从第一轮证据中选择最多三个主要体验问题集中修复；该数量不限制必须处理的事实、安全或关键流程缺陷。

优先顺序：

1. 会误解结果、范围或来源的展示问题。
2. 找不到步骤、返回路径、原文或接入入口的阻碍。
3. 反复操作、长名称拥挤、对齐和留白等可复现的阅读摩擦。

允许改布局、名称、控件状态与焦点行为，但不增加教程式说明面板；优先用主次、就近动作和按需展开表达关系。纯审美偏好先做同记录、同视口对照，不因“感觉还能更漂亮”自动启动整体换肤。

跨入口问题修复后在三个入口复核。仅当同一修复确实需要重复维护时，提取小范围内部共享逻辑；不因 `site/app.js` 较长就整页重写，也不强行让工作台失去 Agent 轨迹与完成态重放职责。

每个修改必须关联第一轮的问题编号、预期用户收益、前后证据和保留测试。没有独立风险的新测试不增加；确认的新缺陷则在合适层补最小回归，并按现有 P0/P1/P2 标准分级。

如果六项任务和接入验证均未发现值得修改的问题，跳过本轮 UI 开发，直接复验收口，不为了迭代而制造改动。

## 5. 第三轮：复验、交付与停止条件

### 工程验收

- 回测被修改的用户任务，并复核其相邻路径；步骤可达、关键事实正确、原值与来源保留。内部走查记录操作路径；人类阅读速度按下述外部验证单独验收。未通过项保留为未通过，不能仅以截图或自动测试绿灯替代。
- 中英接入说明一致；完整阅读组件与低层画布的职责清楚，示例在本地可运行。
- 涉及产品代码修改时，通过 JS、语法、类型、32 场景严格检查与默认三浏览器回归（当前基线 597 次）；测试变化需说明新增/替代的独立风险，不追求固定数量。
- 仅文档修改不机械重跑所有浏览器；运行文档示例及相应验证即可。未修改 Recorder 不重复生成 fixtures；需要触及采集或公共契约时另行确认范围。
- 完成 M1 的防干扰验收，浏览器回归独占服务器并使用独立产物目录。只有引擎相关风险需要时才扩大到全部数据组合，不恢复不必要的日常重复执行。

### 阅读效果证据分层

开发者与独立代理可以先完成任务走查，产出工程验收，不阻塞文档纠错及已经证实的问题修复。但这仍不是陌生用户研究。

建议 Owner 后续协调两位没参与实现、了解基本 Eino 概念的开发者，在不提示操作的情况下分担上述任务，合计覆盖三个来源类型。获得用户同意后才联系他人或接收真实项目记录；记录脱敏后仍须保留必要身份关系，无法保留的关系明确记为不可验证。

没有外部参与者或新项目记录时，可以完成本期工程工作，但“陌生用户可用性”和“真实项目迁移效果”标为待验证，不伪造已达到优秀的结论。小样本通过也只证明这些任务，不推广为所有 Eino 项目都已覆盖。

### 交付与停止

交付包括：中英接入说明、六项任务结果、已修问题的同记录前后对照、回归摘要、剩余问题及证据等级。

接入验证和内部六项任务的正确性/可达性通过、已确认的阻断问题关闭后，本期工程工作结束，进入反馈驱动维护。人类阅读速度和陌生用户理解效果独立标记通过、失败或待验证，不能因工程收口就改成通过。如果关键工程问题暂时无法在边界内解决，则如实交付未完成项并请求范围决策，不无限循环小修，也不把本期工程工作标作完成。

## 6. 条件触发的后续候选

| 候选 | 启动条件 | 未满足条件时 |
| --- | --- | --- |
| 新增真实业务记录 | 现有矩阵无法复现已报告的阅读/归属问题，且获得安全可用的记录 | 不按场景数量扩充 fixtures |
| 大记录性能优化 | 对具体记录测得打开、检索或绘图阻塞，并能固定机器/输入复现 | 保留已有分页、按需绘图和 500 节点保护，不重写渲染器 |
| 更多 Agent 转交关系 | 原始记录提供可靠身份与边界，且当前展示确实遗漏有用事实 | 不猜关联，不扩展 Recorder 或记录协议 |
| 进一步共享内部 UI | 同一问题在两套入口重复修复，能界定稳定的小模块；当前 UI 搜索适配确有重复实现，但尚无结果错误证据 | 不做架构清洗或整页重构，不改公开搜索接口 |

本期明确不做：实时、流式、恢复执行、多运行比较、在线服务、发布、上游仓库改动、新公共 API、推测的因果边和自动补全缺失结果。四项现有采集/归属限制保留为事实边界，不将消除警告数量作为目标。

实施结果和后续触发条件以[本期验收记录](./FIRST_USE_ACCEPTANCE.md)为准；不把已经完成的第一轮任务继续列作下一轮待办。
