# 迭代 11–13：三轮分析、验证、判断、执行

日期：2026-09-23。三轮均围绕已保存、非流式 Eino 结果的静态阅读；不增加实时、执行器、
公共 API 或发布步骤。每轮完成专项验证后才进入下一轮实施。

## 第一轮：同名步骤的身份辨识

**分析与验证。** 默认 Agent 的两次 `get_weather`、真实并发 `lookup_item`，以及嵌套
Workflow 的两个 `Shared step`，在列表中同名。原投影的身份和结果并没有合并，但读者
必须逐个打开来源才能区分。同名子 Agent 还可能复用内部 tool call ID，仅补最后一段
ID 仍不够。

**判断。** 增加必要的来源事实，不给并行调用编造先后次序，不增加解释面板。只有显示
名称发生冲突时才补标签；唯一名称保持简洁。

**执行。** Tool 使用经自身 component I/O 验证的调用 ID，冲突时补完整父调用链或作用域；
Workflow 使用与原始定义和 I/O 对齐的完整节点路径。字段冲突、缺少自身来源、重复身份
或仍无法区分的显示值不猜标签。路径段含分隔符时保留段边界，不把两个不同路径拼成同一身份。

全运行映射贯穿列表、详情、图键盘名称和 Agent 轨迹，搜索、范围切换不会重新生成局部编号。
轨迹关联使用完整作用域和 tool call ID，不使用共享模型证据来决定调用归属。原始名称、
标准投影、回调返回的节点对象、业务值、因果边和原文导出不变。

专项三浏览器 **45 / 45** 通过；默认示例另有 3 项 Chromium 回归通过。更新旧测试的
精确显示名称预期，保留标准投影、业务值与来源断言，不以模糊匹配替代验收。

## 第二轮：可见字段可检索

**分析与验证。** 中文页面显示“成功”却检索出 0 条；`evaluate · 第 2 次`、SDK 的
`Succeeded`、完整 Workflow 路径和部分含 Unicode/标点的原始 ID 也无法检索。
另一方面，旧索引包含错误摘要正文，与“名称、ID 或状态”的提示不一致。

**判断。** 搜索覆盖结构性名称、原始身份、可见状态和已确认的调用次数，不自动索引业务
正文、错误内容或注释性解释。检索不能改变执行归属，也不能把未确认或仅计划节点标成成功。

**执行。** 共享索引加入中英显示别名、准确来源路径和原始关联 ID；调用次数复用第一轮及
上一轮的严格来源规则。`Call 2`、`第 2 次`、`第2次` 必须匹配已确认次数或某个真实名称/
ID 内的连续字面短语，不能由无关 callback ID 的 `call` 和 `:2` 拼凑命中。真正名为
`Call 2` 的节点仍可搜索，不将其设成保留名称。

普通查询保持关键词 AND、大小写不敏感、来源顺序、分页及范围/异常过滤交集。状态词不是
专用查询语法：例如某个运行 ID 本身含 `failed`，英文关键词仍会按 ID 命中。此行为有明确
回归断言。中文状态、用户输入/助手输出、完整路径和中英次数均可检索；正文通过详情和来源查看。

专项三浏览器 **45 / 45** 通过。人工复验默认示例，“成功”从 0 条恢复为实际 5 个成功
步骤；Graph 次数、Workflow 局部路径与 Agent 原始调用 ID 均验证了精确结果来源。

## 第三轮：错误采集状态与独立检查

**分析与验证。** 真实记录的派生边界用例证明：节点错误未传递脱敏、截断和遗漏状态；
验收脚本遗漏 `truncated`，既会拒绝正确展示，也会放过把截断错误标成完整可用的错误投影。

**判断。** 同时修复阅读链路和验收规则。错误仍是错误，捕获完整性是另一件事；不能因错误
发生就污染独立业务输出，也不能让“执行失败”掩盖“错误正文未采集”。

**执行。** 错误频道读取自身的 capture 标记；运行摘要、局部结果、步骤补充错误和 Agent
轨迹按原始引用中的精确错误消息派生读取状态。只有布尔 `true` 生效；遗漏优先，脱敏优先
于截断。没有精确信封索引的诊断不猜归属，错误字段路径不能影响邻近正文；Workflow 快照
整体的 capture 标记不套到内部节点错误。

遗漏时只显示未采集状态和原因，不显示或复制 Recorder 的占位提示为真实错误正文。
占位提示、脱敏后文字、截断后文字和完整源记录始终保留在 Raw/来源/原文导出中。
公共 `run.issues` 的消息与来源合同不改。多个精确来源的捕获状态冲突时不选赢家，读取层
保守返回无正文并保留来源；目前未增加专用的捕获冲突状态。

验收脚本使用独立来源判定，不复用生产 helper 来计算期望。新增真实记录拷贝的状态变体，
以及抹标记、换来源、改遗漏原因、恢复占位正文等错误投影对照。它们是边界/变异测试，
不是新增真实 Recorder 执行；原有 32 份场景不改写。

交叉审查还复现并修复了同事件混合结果边界：当 Agent 事件同时记录错误和独立 Tool
返回值时，轨迹不能把错误的遗漏标记套到业务返回值上。独立返回值继续展示；只有准确
指向该消息值的诊断可以限定其完整性，错误保留自己的采集状态。

新增错误边界专项 **18 / 18** 通过；补充混合事件修复后的错误/正文一致性专项
**36 / 36** 通过，均覆盖 Chromium、Firefox、WebKit。既有长错误与正文回归另有
27 项通过；独立复核检查了精确字段路径和来源隔离。
