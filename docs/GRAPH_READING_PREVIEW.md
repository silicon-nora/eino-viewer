# Graph 工作台体验试版

## 范围

参考已验收 Agent 的精简原则，本轮只优化工作台 Graph；Agent、Workflow、完整嵌入组件与离线版保持原样。Graph 方案仍待 Owner 确认，确认后再考虑抽取共享展示，不将未定稿方案当作三入口标准。

公开 API、Recorder、记录格式、原始数据、执行关系、访问顺序及上游仓库不改。不增加实时、流式、执行或发布功能。

## 阅读设计

以下描述首版与合并版；当前流程定义方案见文末。旧合并版解决重复方框，但画的仍是父子调用关系，不能表达 Graph 的真实定义回环，不能作为流程展示验收完成的依据。

- 执行路径作为主区，步骤列表用于搜索、键盘选择和重复访问定位，右侧直接读输入／输出。
- 正常运行的整次结果收为可展开摘要条，保留耗时；失败／取消／中断自动展开原始原因与有唯一关联的定位操作。详情仍默认首项，不用中间节点的输出代替根结果。
- 移除 Graph 的原始记录编辑、技术详情、证据目录、重复详情按钮、主题／方向设置及重复成功标签。只隐藏已确认成功，异常、未完成、仅定义、采集缺失／脱敏／截断继续明确表达。
- 保留图的缩放、适应画布和主动折叠。绘图保护仍按当前完整范围判断，不用搜索结果绕过 500 节点门限。
- 保留每次真实访问的身份与原值，例如 `evaluate` 的第 1／2／3 次。图可合并来源身份已确认且兼容画布的重复节点，但不因同名推断合并；步骤与详情始终逐次保留，不用 Workflow 依赖排序改写 Graph。
- 只有一个完整平层范围时不重复展示调用目录；多个范围仍保留必要的选择与返回导航。
- 详情先输入后输出，原文完整显示；没有 I/O 复制和关闭按钮，保留 Escape 返回触发项。主结果正文的原值复制保留。

视觉沿用已认可的浅色、蓝色和本地字体。宽屏为紧凑步骤栏、主要路径区与 320px 详情栏；中等宽度详情下移；手机按路径、步骤、详情排列。图高随展示节点数增加并封顶，不改变原始节点和连线数据。

## 重复节点合并

在 Owner 认可步骤、图、输入输出三部分后，仅优化图上的重复展示：

- 有来源证明的同一 Graph 节点只画一个框，标明“执行 N 次”；有异常时标明对应次数。成功样例从 8 个框、7 条边变为 5 个框、4 条边；`evaluate` 的 3 次、`revise` 的 2 次各自合并。失败样例从 5 个框变为 4 个框，`evaluate` 显示“执行 2 次 · 1 次失败”。
- 步骤列表保留每次真实访问；重复节点的详情提供“执行记录”选择。每次选择始终读取该次输入、输出、错误、时间和来源，不显示拼接正文或虚构总耗时。
- 从图选择节点时，已选中的组内调用继续保留；否则先定位失败等异常，再取源序首项。重复点击不会暗中轮换调用。选择次数会同步步骤、图和详情，仅清除隐藏目标的过滤。
- 合并身份基于完整运行内已验证的回调边界、run、entity、完整 address／nodePath、component 及父调用身份。显示名称不是身份；不完整、重叠或关联不明的记录保留独立节点。
- 只合并同端点、同种类、同元数据的真实边，并保留全部原边 ID。不根据访问先后制造控制转移，不把声明分支标成执行事实。
- 合并后若产生当前画布不能表达的自环、有向环或冲突连线，保留展开图。安全判断基于完整运行，子范围不会改变节点身份；500／501 保护仍按原始完整范围计数，不被图合并或搜索绕过。
- 只调整工作台；公开 API、Agent、Workflow、嵌入／离线、Recorder 和上游仓库均未改。

## Graph 流程定义方案

### 解决的问题

`graph-multistep-loop-success` 的定义含 `evaluate → revise → evaluate`，而执行记录的边是根 Graph 到每次调用的父子关系。合并父子关系不会生成循环；也不能根据回调先后伪造运行时跳转。因此将中间图改用可靠的 Graph 定义，执行实例继续留在左侧与详情中。

### 展示分工

- 左侧「步骤」：真实记录顺序，每次访问独立；搜索只影响列表。
- 中间「流程」：定义节点只画一次；固定连接为实线，条件分支为虚线，均带箭头。循环通过外侧回线表达，自循环保留。仅用紧凑图例说明线型，不增加教程面板。
- 节点：已关联记录显示执行次数，异常显示对应次数；正常不重复标成功。没有观测的定义节点显示「未观测到执行」，没有执行记录的图显示「仅定义」。起点／终点只是结构边界。
- 右侧：点击已执行节点保留当前组内访问，否则优先异常、再取首项；下拉切换每次原值。点击未观测节点只说明该状态，不借用根结果或其他节点正文。
- 根 Graph 的输入输出仍可从默认步骤／整次结果读取；根调用不映射成定义的起点。
- 名称：来源没有自定义名称、仅回退为 `Lambda` 等组件名时，步骤和详情采用已确认对应的定义节点名称；来源明确给出的名称（即使恰好叫 `Lambda`）原样保留，必要时次行展示对应的定义名称。搜索支持该显示名称，不修改公开搜索接口或原始节点。

### 技术边界

新增工作台私有的纯拓扑模型与支持环的 SVG 画布，不改公开入口和 DAG 依赖。模型将定义边与执行访问分开保存：边只来自 `edges` 和 `branches`，节点关联校验原始来源中的 run、address、nodePath、component 与规范节点的一致性，不用显示名称猜测。定义和原始记录不变；无法关联的执行仍保留在步骤中。

当前仅在整次范围（或包含整次执行的完整分组）使用根定义；无法对应定义的局部范围明确回退为「调用关系」。不能借根定义伪装子调用流程。没有可靠定义仍保留原调用关系画布。

继续按完整范围的规范节点数保护绘图，并同时保护定义节点数：任一超过 500 都需要主动绘制。搜索、进入小范围再返回、按定义合并都不能绕过。隐藏容器延迟初始化，过期挂载和销毁回调不得重建图。语言切换通过内部状态保存选中与视口，不模拟节点点击。

视觉沿用浅色、蓝色、本地字体与三栏；把视觉重点放在可辨识的回环方向，其他控件保持克制。Graph 仍是工作台试版，Agent、Workflow、嵌入／离线、Recorder、公开 API 和上游仓库均不调整。
